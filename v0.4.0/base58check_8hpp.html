Detailed Description

Base58check: base58 of a payload and the first four bytes of its double SHA-256.

Overview

The text of Bitcoin's P2PKH and P2SH addresses (version byte 0x00 / 0x05 and a HASH160), Wallet Import Format keys (0x80, the key, and 0x01 for a compressed public key), BIP-32 extended keys (xprv / xpub, 78-byte payloads), TRON addresses (0x41) and, with XRPL's alphabet, XRP Ledger addresses. The checksum catches typing errors: decoding verifies it and refuses the text on any mismatch.

  • base58check_encode<MaxBytes>(payload) / base58check_decode<MaxBytes>(text): any payload up to the cap.
  • base58check_encode_exact(std::array<std::uint8_t, N>) / base58check_decode_exact<N>(text): a payload of a fixed size, such as the 78 bytes of an extended key; the decode refuses any other length.
  • base58check_checksum(payload): the four bytes alone.
Relationships
  • address/base58.hpp: the encoding underneath and its alphabets.

Implementations and variants

One. SHA-256 is the library's interim implementation (detail/hashes.hpp), to become snicholls-core's when core releases its hashes; nothing here changes then.

Guarantees and contracts
  • constexpr, noexcept, no allocation.
  • Not constant time (see base58.hpp): addresses are public; for text that carries a secret (WIF, xprv) see "Known issues".
  • The checksum comparison itself is constant time (ct::equal), which costs nothing and leaves no oracle on how many checksum bytes matched.
Errors

errc::invalid_length (over the cap; a decoded body shorter than the 4 checksum bytes; a wrong length for the exact form), errc::invalid_character, errc::invalid_checksum.

Examples
namespace address = snicholls::crypto::address;
// Version 0x00 and the HASH160 of private key 1's compressed public key (a published test key)
constexpr auto payload = snicholls::crypto::test::hex<21>("00751e76e8199196d454941c45d1b3a323f1433bd6");
const auto bitcoin = address::base58check_encode_exact(payload); // fixed size: cannot fail
const auto xrpl = address::base58check_encode_exact(payload, address::xrpl_base58);
const auto checksum = address::base58check_checksum(payload);
const auto decoded = address::base58check_decode_exact<21>("1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMH");
const auto typo = address::base58check_decode("1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMh"); // last letter's case
const auto any = address::base58check_decode("1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMH"); // any length up to 128
const auto encoded = address::base58check_encode(std::span<const std::uint8_t>(payload));
Performance

benchmarks/address/base58_benchmark.cpp, macOS x86-64 (Xeon W-3245, 3.2 GHz), Apple Clang 17, Release, 2026-11-20: an address encodes in 1.4 us and decodes in 1.2 us; a 78-byte extended key encodes in 7.4 us and decodes in 5.0 us (base58's quadratic cost dominates; the double SHA-256 is about 0.9 us of each).

Tests and demos

tests/address/base58check_test.cpp (the addresses and WIF of private key 1, the BIP-32 test vector 1 master key, XRPL's special addresses, a corrupted checksum in every position), demos/address/base58check_demo.cpp.

Dependencies

<array>, <cstddef>, <cstdint>, <span>, <string_view>; core's result.hpp and containers/inplace_vector.hpp.

Known issues and gotchas

A WIF key or an xprv passes through this codec in variable time and lives briefly in its buffers, which are wiped before return; the text the caller receives is the caller's to wipe. The same reasoning as base58's applies: this text exists only at the boundary with a person.

Status

Experimental (0.1).

Detailed Description

ECDSA on P-256 with SHA-256 (JOSE's ES256): keys, RFC 6979 signing, verification, JOSE and DER forms.

Overview
  • private_key (32 bytes, 1 to n - 1) and its public_key (SEC1 compressed or uncompressed).
  • sign(key, hash): RFC 6979 deterministic nonces (HMAC-SHA256), the signature (r, s) as computed; s is not reduced to the lower half, as ES256 and FIPS 186-5 do not require it.
  • verify(key, hash, signature): FIPS 186-5 / SEC 1 verification, either s accepted.
  • signature::from_jose / jose(): JWS's 64-byte r || s; from_der / der(): strict DER.

The hash is the SHA-256 of the message, 32 bytes (for a JWS, of the ASCII header.payload); with P-256's 256-bit order it is used whole, reduced modulo n.

Relationships
  • p256/point.hpp, p256/scalar.hpp; secp256k1/rfc6979.hpp (the nonce generator, for any 256-bit order); detail/ecdsa_der.hpp.
  • Group: P-256.
Implementations and variants

One: k G and the private-key arithmetic in constant time (point::mul, Fermat's inverse); verification with point::mul_add_public in variable time.

Guarantees and contracts
  • private_key, public_key() and sign: constant time in the private key and the nonce. Revealed on purpose (ct::declassify): whether a key's bytes are in range, and the RFC 6979 retry on r or s of zero (probability about 2^-256). The key is held in secret_bytes<32>; intermediates are wiped.
  • verify, public_key::parse, signature::from_der: variable time; public data only.
  • constexpr, noexcept, no allocation.
Errors

errc::invalid_private_key for a key of 0 or at least n; errc::invalid_public_key for an encoding that is not SEC1 compressed or uncompressed of a point on the curve; errc::invalid_signature for r or s outside 1 to n - 1, DER that is not DER, or a signature that does not verify.

Examples
namespace p256 = snicholls::crypto::p256;
// RFC 6979's published test key; a real key comes from a CSPRNG
const auto key = p256::private_key::from_bytes(hex<32>("c9afa9d845ba75166b5c215767b1d6934e50c3db36e89b127b8a622b120f6721")).unwrap();
const p256::public_key pub = key.public_key();
const auto hash = sha256("sample"); // for a JWS: SHA-256 of "header.payload"
const p256::signature sig = p256::sign(key, hash); // RFC 6979: deterministic
const auto jose = sig.jose(); // ES256's 64-byte r || s
const auto ok = p256::verify(pub, hash, p256::signature::from_jose(jose));
const auto wrong = p256::verify(pub, sha256("other"), sig); // errc::invalid_signature

Dependencies

Known issues and gotchas

Hash the message first: sign and verify take the 32-byte SHA-256. JOSE's signature is r || s, never DER.

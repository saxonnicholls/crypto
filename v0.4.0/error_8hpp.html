Detailed Description

snicholls::crypto::errc: every expected failure in snicholls-crypto, one enumeration.

Overview

Every operation that can fail on its input (a key out of range, a signature that does not verify, a mnemonic with a bad checksum, a path that is not hardened where it must be) returns snicholls::result<V, errc>. One enumeration for the whole library, so a caller that handles a wallet flow end to end (words to seed to key to signature) matches on one type. Exceptions are kept for the unexpected; nothing here throws.

  • snicholls::result (core's result.hpp): the carrier. SNICHOLLS_TRY_ASSIGN propagates.

Guarantees and contracts

to_string is constexpr and noexcept; the text never contains key material, so an error may be logged.

None of its own.

Examples
// A function that can fail on its input returns result<V, errc>; the caller matches on the value
snicholls::result<int, snicholls::crypto::errc> word_count(int words)
{
if (words % 3 != 0 || words < 12 || words > 24)
return snicholls::err(snicholls::crypto::errc::invalid_mnemonic_length);
return snicholls::ok(words);
}
int main()
{
const auto good = word_count(12);
const auto bad = word_count(13);
std::printf("12 words: %s\n", good ? "ok" : "error");
std::printf("13 words: %s\n", std::string(snicholls::crypto::to_string(bad.unwrap_err())).c_str());

Known issues and gotchas

A failed verification is errc::invalid_signature, the same value for every reason a signature is wrong (bad range, wrong key, wrong message): a verifier should not tell an attacker which check failed.

Detailed Description

snicholls::crypto::ct: masks, selection, swaps and comparisons whose timing does not depend on the data.

Overview

The building blocks of every secret-dependent computation in the library. A condition on secret data is never a branch or an index: it becomes a mask (all ones or all zeros) and the two candidate results are combined with it. value_barrier hides a value from the optimiser at run time, so it cannot prove a mask is 0 or 1 and turn the selection back into a branch, which compilers do.

Use these for anything that touches a private key, a nonce, a seed or an intermediate derived from one. Data that is public (a signature being verified, a public key) may use ordinary code.

Relationships
  • secret.hpp: the buffer that holds secrets and wipes them.
  • Every field and scalar type in secp256k1/ and curve25519/ is built on these.
  • Group: snicholls-crypto.
Implementations and variants

One. The barrier is an empty asm with the value as an in-out register operand on GCC and Clang, and a volatile round trip elsewhere (MSVC). In a constant expression it is the identity.

Guarantees and contracts

Every function is constexpr and noexcept. Timing depends only on the sizes of the arguments, never on their values. That is a property of the source and of the compilers the library is tested with (see "Known issues").

Errors

None.

Examples
namespace ct = snicholls::crypto::ct;
const std::uint64_t secret_bit = 1; // say, a bit of a private key
const std::uint64_t mask = ct::mask_from_bit(secret_bit);
std::uint32_t a = 10, b = 20;
ct::conditional_swap(mask, a, b); // swapped, with no branch on secret_bit
const auto chosen = ct::select<std::uint32_t>(ct::mask_less(a, b), a, b); // min(a, b) without a branch
const std::array<std::uint8_t, 4> tag{1, 2, 3, 4}, expected{1, 2, 3, 4};
const bool same = ct::equal(tag, expected); // a MAC check that does not stop at the first difference
Performance

Not benchmarked on its own: a handful of instructions each; the curve benchmarks measure them in use.

Tests and demos

tests/constant_time_test.cpp, demos/constant_time_demo.cpp. The secret-marking check (tests/ct/secret_marking.cpp, run under Valgrind in make ubuntu) runs the signing and derivation paths with the secret inputs marked undefined, so a branch or an index on them is reported.

Dependencies

<cstddef>, <cstdint>, <span>, <type_traits>.

Known issues and gotchas

Constant time in C++ is a property no standard promises: a compiler may still emit a branch. The barrier and the mask style defeat the transformations GCC and Clang are known to make; the Valgrind check is the evidence for the built binaries, and only for the compilers and flags it ran with.

Status

Experimental (0.1).

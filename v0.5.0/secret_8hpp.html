Detailed Description

secret_bytes<N>: a fixed-size buffer for key material that is wiped when it dies, and secure_wipe.

Overview

Private keys, seeds, chain codes, nonces and every intermediate derived from them live in a secret_bytes<N>. It owns N bytes inline (no allocation), zeroes them in its destructor with writes the optimiser may not remove, and makes copying explicit: the copy constructor is deleted, clone() is the one way to a second copy, and a move wipes the source. The bytes are reached through reveal(), as core's snicholls::secret, so every use of key material is easy to find.

Use it for anything that would let an attacker sign, derive or decrypt. Do not use it for public data: a public key or a signature is a plain std::array.

Relationships
  • snicholls::secret<T> (core): the masking wrapper for secrets in configuration and logs; this is its cryptographic counterpart, fixed-size and wiped.
  • constant_time.hpp: comparisons on secrets.
  • Group: snicholls-crypto.
Implementations and variants

One. secure_wipe writes through a volatile pointer and ends with a compiler barrier; in a constant expression it is a plain fill.

Guarantees and contracts
  • Not thread-safe (a value type). Every member is noexcept; construction and destruction are constexpr.
  • The destructor wipes; a moved-from buffer is all zeros.
  • It is not printable: no operator<<, no print, so acout and print_to refuse it at compile time.
  • Equality is constant-time (ct::equal).
Errors

None.

Examples
std::array<std::uint8_t, 32> from_somewhere{};
from_somewhere[0] = 0x42;
snicholls::crypto::secret_bytes<32> key(std::move(from_somewhere)); // takes the bytes, wipes the array
snicholls::crypto::secret_bytes<32> second = key.clone(); // copies are explicit
snicholls::crypto::secret_bytes<32> moved = std::move(key); // a move wipes the source
const std::uint8_t first = moved.reveal()[0]; // reveal(): the one way in
Performance

Not benchmarked: a wipe is N byte stores.

Known issues and gotchas

Wiping cannot reach copies the program never sees: registers, spilled stack slots in callees, pages the operating system swapped out, and copies the caller made before handing the bytes over. Lock the memory and disable core dumps in the program if those matter; that needs the operating system and is outside this library.

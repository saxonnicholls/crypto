Detailed Description

JOSE's ECDH-ES key agreement (RFC 7518 4.6, RFC 8037 for X25519): the key a JWE's content or key-wrapping key comes from, on X25519 or P-256.

Overview

A JWE with "alg": "ECDH-ES" or "ECDH-ES+A256KW" carries the sender's ephemeral public key (epk). Both sides compute the ECDH shared secret Z and put it through the Concat KDF (SHA-256, NIST SP 800-56A) with an OtherInfo built from the header, which gives:

  • for direct key agreement ("alg": "ECDH-ES"), the content encryption key itself: the algorithm in the OtherInfo is the enc value ("A256GCM") and the key is as long as enc needs;
  • for key agreement with key wrapping ("alg": "ECDH-ES+A256KW"), the key-encryption key: the algorithm is the alg value and the key is the wrap's (32 bytes for A256KW), which unwraps the JWE's encrypted key (aead/aes_key_wrap.hpp) to the content encryption key.
Algorithm in the OtherInfo N, bytes
A128GCM, ECDH-ES+A128KW 16
A192GCM, ECDH-ES+A192KW 24
A256GCM, ECDH-ES+A256KW, A128CBC-HS256 32
A192CBC-HS384 48
A256CBC-HS512 64

apu and apv are the header's values base64url-decoded (empty when absent). The functions:

  • ecdh_es_x25519<N>(own secret, peer's key, algorithm, apu, apv): X25519 ("crv": "X25519", RFC 8037).
  • ecdh_es_p256<N>(own key, peer's key, algorithm, apu, apv): P-256 ("crv": "P-256").
  • ecdh_es_kdf<N>(z, algorithm, apu, apv): the KDF alone, for a shared secret computed elsewhere.

The recipient passes its static private key and the epk; the sender passes a fresh ephemeral private key and the recipient's public key, and puts the ephemeral public key in the header. The JOSE text (base64url, JSON) is the caller's: this header takes and returns bytes.

Relationships
  • curve25519/x25519.hpp, p256/ecdh.hpp: the shared secrets; core's hash/kdf.hpp: jwa_concat_kdf.
  • aead/aes256_gcm.hpp (A256GCM content encryption, with the ASCII of the protected header as the associated data) and aead/aes_key_wrap.hpp (A256KW).
  • Group: JOSE.
Implementations and variants

One: core's jwa_concat_kdf with SHA-256, its hash states wiped (detail/hashes.hpp).

Guarantees and contracts
  • Constant time in the private key, the shared secret and the derived key; the peer's key, the algorithm, apu and apv are public (their lengths and values decide only how much is hashed). Revealed on purpose (ct::declassify): that X25519 gave the all-zero secret, or that d Q on P-256 is the identity (both errors).
  • The derived key is in secret_bytes<N>; Z and every hash state are wiped.
  • constexpr, noexcept, no allocation.
Errors

ecdh_es_x25519: errc::small_order when the peer's key has small order (the all-zero shared secret: refuse the JWE). ecdh_es_p256: errc::invalid_public_key when the peer's point is not on the curve. ecdh_es_kdf cannot fail.

Examples
// RFC 7518 appendix C: Bob, the recipient, derives the A128GCM key from Alice's epk ("apu": "QWxpY2U", "Alice";
// "apv": "Qm9i", "Bob"). The keys are the RFC's published test keys
const auto bob = p256::private_key::from_bytes(hex<32>("5449836690d75caf29f0dd029ddb31b3ddb8aba9d2d515c5012465e817d4a9dc")).unwrap();
const auto epk = p256::private_key::from_bytes(hex<32>("d3f3716913d4310a0026de741b3f18893afc8114f0c84682ba677e313a13988a")).unwrap().public_key();
const std::array<std::uint8_t, 5> apu{'A', 'l', 'i', 'c', 'e'};
const std::array<std::uint8_t, 3> apv{'B', 'o', 'b'};
auto cek = jose::ecdh_es_p256<16>(bob, epk, "A128GCM", apu, apv); // "alg": "ECDH-ES": the algorithm is enc
// ECDH-ES+A256KW on X25519 (RFC 7748's test secrets): the sender wraps a CEK and encrypts, the recipient
// derives the same key-encryption key (the algorithm is alg), unwraps and opens
const secret_bytes<32> ephemeral(hex<32>("77076d0a7318a57d3c16c17251b26645df4c2f87ebc0992ab177fba51db92c2a"));
const secret_bytes<32> recipient(hex<32>("5dab087e624a8a4b79e17f8b83800ee66f3bb1292618b6fd1c2f8b27ff88e0eb"));
const auto kek_sender = jose::ecdh_es_x25519<32>(ephemeral, x25519::public_key_from_secret(recipient), "ECDH-ES+A256KW").unwrap();
const auto content_key = hex<32>("000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f");
const auto iv = hex<12>("000000000000000000000001");
constexpr std::string_view header = "eyJhbGciOiJFQ0RILUVTK0EyNTZLVyIsImVuYyI6IkEyNTZHQ00ifQ"; // the protected header, as sent
const std::span<const std::uint8_t> aad(reinterpret_cast<const std::uint8_t*>(header.data()), header.size());
const std::array<std::uint8_t, 5> message{'h', 'e', 'l', 'l', 'o'};
std::array<std::uint8_t, 40> encrypted_key{};
std::array<std::uint8_t, 5> ciphertext{};
const bool wrapped = aead::aes256_key_wrap(kek_sender.reveal(), content_key, encrypted_key).is_ok();
const auto tag = aead::aes256_gcm_seal(content_key, iv, aad, message, ciphertext).unwrap();
const auto kek = jose::ecdh_es_x25519<32>(recipient, x25519::public_key_from_secret(ephemeral), "ECDH-ES+A256KW").unwrap();
std::array<std::uint8_t, 32> unwrapped{};
std::array<std::uint8_t, 5> opened{};
const bool ok = aead::aes256_key_unwrap(kek.reveal(), encrypted_key, unwrapped).is_ok() &&
aead::aes256_gcm_open(unwrapped, iv, aad, ciphertext, tag, opened).is_ok();
Performance

One X25519 or P-256 scalar multiplication and, for N up to 32, one SHA-256 block or two. See BENCHMARKS.md, benchmarks/jose/ecdh_es_benchmark.cpp.

Known issues and gotchas
  • The algorithm is enc for direct agreement and alg with key wrapping: the wrong one gives a wrong key, and the JWE then fails authentication, not decoding.
  • N must be the length the algorithm needs (the table): it is in the OtherInfo, so a longer key is not a prefix of a shorter one's derivation.
  • The sender's ephemeral key must be fresh for every JWE, from a system random source; this library takes it, it does not make it.
  • Check the epk's curve against the recipient's key before calling: X25519 bytes on P-256 do not decode, but a P-256 key is not refused by X25519.

Detailed Description

Bech32 (BIP-173), bech32m (BIP-350), 8-to-5-bit regrouping, and segwit addresses.

Overview

Bech32 is a human-readable part (the HRP: bc, tb, cosmos, ...), the separator 1, data in a 32-symbol alphabet, and a six-symbol BCH checksum that detects any four substitutions. Bech32m (BIP-350) changes only the constant the checksum is xored with, closing bech32's insertion weakness. Segwit addresses carry a witness version (0 to 16) and a program of 2 to 40 bytes: version 0 uses bech32 and a 20- or 32-byte program, versions 1 and up (taproot is 1) use bech32m.

  • bech32_encode<MaxLength>(hrp, values, variant) / bech32_decode<MaxLength>(text): 5-bit values, any HRP.
  • convert_bits<From, To, Pad, N>(in): regrouping, with BIP-173's padding rules when Pad is false.
  • segwit_encode(hrp, version, program) / segwit_decode(hrp, address): addresses, every BIP-173 and BIP-350 rule; witness_program::script_pubkey() gives the output script.

Decoding is strict, as both BIPs require: printable ASCII only (33 to 126), no mixed case (either all lower or all upper; the result is lower case), the last 1 is the separator, an HRP of 1 to 83 characters, at least six data symbols, and at most 90 characters in all unless MaxLength is raised (Lightning invoices exceed 90).

Implementations and variants

One: the BIPs' reference algorithm, written for fixed buffers.

Guarantees and contracts
  • Every function is constexpr and noexcept; nothing allocates.
  • Not constant time: addresses are public data.
  • Encoding writes lower case; decoding accepts all-upper (QR codes) and returns lower case.
Errors

errc::invalid_length (over MaxLength, fewer than six checksum symbols, a value list too long), errc::invalid_character (outside 33 to 126, or a data symbol outside the alphabet, or a value of 32 or more), errc::non_canonical (mixed case; padding of five bits or more, or non-zero padding, when regrouping), errc::invalid_hrp (no separator, an empty or too long HRP, or not the HRP expected), errc::invalid_checksum (wrong checksum, or the wrong variant for the witness version), errc::invalid_witness_version, errc::invalid_witness_program.

Examples
namespace address = snicholls::crypto::address;
// A P2WPKH program (HASH160 of a published test key) as a mainnet address: version 0, so bech32
constexpr auto program = snicholls::crypto::test::hex<20>("751e76e8199196d454941c45d1b3a323f1433bd6");
const auto p2wpkh = address::segwit_encode("bc", 0, program);
// Upper case is accepted (QR codes); the program comes back with its output script
const auto decoded = address::segwit_decode("bc", "BC1QW508D6QEJXTDG4Y5R3ZARVARY0C5XW7KV8F3T4");
const auto script = decoded->script_pubkey();
// A version-1 address written with bech32 instead of bech32m is refused (BIP-350)
const auto wrong = address::segwit_decode("bc", "bc1p0xlxvlhemja6c4dqv22uapctqupfhlxm9h8z3k2e72q4k9hcz7vqh2y7hd");
// Raw bech32m with an HRP of your own: regroup bytes into 5-bit values, encode, decode
const auto five = address::convert_bits<8, 5, true, 32>(program);
const auto text = address::bech32_encode("demo", std::span<const std::uint8_t>(five->data(), five->size()),
address::bech32_variant::bech32m);
const auto raw = address::bech32_decode(std::string(text->data(), text->size()));
const auto bytes = address::convert_bits<5, 8, false, 32>(std::span<const std::uint8_t>(raw->values.data(), raw->values.size()));
const std::uint32_t check = address::bech32_polymod("demo", {}); // the BCH polymod, for those who need it
Performance

benchmarks/address/bech32_benchmark.cpp, macOS x86-64 (Xeon W-3245, 3.2 GHz), Apple Clang 17, Release, 2026-11-20: a P2WPKH address encodes in 0.22 us and decodes in 0.33 us; a taproot address in 0.31 us and 0.48 us.

Tests and demos

tests/address/bech32_test.cpp: every valid and invalid string and address of BIP-173 and BIP-350, demos/address/bech32_demo.cpp.

Dependencies

<array>, <cstddef>, <cstdint>, <span>, <string_view>; core's result.hpp and containers/inplace_vector.hpp.

Known issues and gotchas

BIP-173's own invalid list includes a checksum computed over the upper-case HRP (A1G7SGD8): the checksum is always over the lower-case form, and this library follows the BIP.

Status

Experimental (0.1).

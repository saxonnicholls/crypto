Detailed Description

RSA signature verification (RFC 8017): RSASSA-PKCS1-v1_5 and RSASSA-PSS with SHA-256 (RS256, PS256).

Overview

Verification only: checking signatures made by others with public keys they publish (JWKS n and e, an X.509 SubjectPublicKeyInfo, a PKCS#1 RSAPublicKey). There is no RSA signing or decryption here, so no RSA private key ever enters this library.

  • Keys: public_key::from_components(n, e) (big-endian bytes, as a JWK's n and e are after base64url decoding), public_key::from_spki_der (a SubjectPublicKeyInfo with the rsaEncryption identifier, or a bare RSAPublicKey) and public_key::from_pkcs1_der (a bare RSAPublicKey only). Moduli of 2048 to 4096 bits; odd exponents from 3 to 2^64 - 1.
  • verify_pkcs1v15_sha256: RFC 8017 section 8.2.2 with EMSA-PKCS1-v1_5 and SHA-256 (JOSE's RS256). The encoded message is rebuilt from the hash and compared whole, so no parser of the padding or the DigestInfo exists to be lenient (the class of forgery behind Bleichenbacher's 2006 low-exponent attack is impossible by construction). The DigestInfo is DER with its NULL parameters; the form without them, which RFC 8017 does not define for SHA-256 and Wycheproof marks "acceptable", is refused.
  • verify_pss_sha256: RFC 8017 section 8.1.2 with EMSA-PSS, SHA-256 and MGF1-SHA-256 (JOSE's PS256), for a given salt length (32 by default, as PS256 uses; 0 to the maximum the modulus allows).
  • Each has a prehashed form taking the 32-byte SHA-256 of the message.

Strict input (CLAUDE.md rule 8): a signature must be exactly as long as the modulus, and below it; n and e given as components must have no leading zero byte (JWK's rule, RFC 7518 section 6.3.1); DER must be DER (minimal lengths and integers, nothing trailing), with the rsaEncryption algorithm's NULL parameters present.

Relationships
  • detail/montgomery.hpp: the modular arithmetic; detail/hashes.hpp: SHA-256 (core's).
  • Group: RSA.
Implementations and variants

One: s^e mod n by left-to-right square-and-multiply in Montgomery form (CIOS multiplication, 64-bit limbs), the modulus's Montgomery constants computed when the key is made.

Guarantees and contracts
  • Variable time; public data only. Every input is public (a public key, a message, a signature), so the arithmetic runs over the modulus's length and the exponent's bits, and comparisons stop at the first difference. There is no secret on any path in this header.
  • Everything is constexpr and noexcept; no allocation (a key holds fixed arrays for 4096 bits, about 1 KB).
  • Thread safety: a public_key is a value; concurrent verifications with one key are safe.
Errors

errc::invalid_public_key for a key outside the limits or badly encoded, errc::non_canonical for a component with a leading zero byte, errc::invalid_signature for a signature of the wrong length, at or above the modulus, or that does not verify, errc::invalid_length for a PSS salt length the modulus cannot hold.

Examples
namespace rsa = snicholls::crypto::rsa;
const auto key = rsa::public_key::from_spki_der(view(spki)).unwrap(); // a PEM "PUBLIC KEY", base64-decoded
const auto same = rsa::public_key::from_components(view(n), view(e)); // a JWK's n and e, base64url-decoded
const std::span<const std::uint8_t> message{}; // for a JWS: "header.payload"
const auto pkcs1 = rsa::verify_pkcs1v15_sha256(key, message, view(rs256)); // RS256
const auto pss_ok = rsa::verify_pss_sha256(key, message, view(ps256)); // PS256, salt length 32
auto tampered = rs256;
tampered[100] ^= 1;
const auto refused = rsa::verify_pkcs1v15_sha256(key, message, view(tampered)); // errc::invalid_signature
Performance

One modular exponentiation with the public exponent: 17 Montgomery multiplications for e = 65537. See BENCHMARKS.md, benchmarks/rsa/rsa_benchmark.cpp.

Dependencies

<array>, <cstdint>, <span>; core's result.hpp and SHA-256.

Known issues and gotchas

A JWK's n and e are base64url text: decode them first (this library takes bytes). PEM is base64 text around DER: strip the armour and decode it first. Pick the scheme from the token or the protocol, never by trying both.

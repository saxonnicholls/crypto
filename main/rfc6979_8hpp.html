Detailed Description

secp256k1::rfc6979: deterministic ECDSA nonces (RFC 6979, HMAC-SHA256), for any 256-bit group order.

Overview

ECDSA leaks the private key if a nonce repeats or is biased, so the nonce is derived from the key and the message hash with HMAC_DRBG (RFC 6979 section 3.2), and needs no random generator. The generator yields candidates k in [1, q - 1] in order; ECDSA takes the first that gives r != 0 and s != 0. Optional extra data (section 3.6, what libsecp256k1 calls ndata) mixes 32 more bytes into the derivation, for signers that want fresh randomness without giving up determinism's protection.

The group order is a parameter, so the RFC's own appendix A.2.5 vectors (P-256 with SHA-256) test it exactly; the signer uses secp256k1's n.

Implementations and variants

One: hlen = qlen = 256 (SHA-256, a 256-bit order), the case of every curve this library signs on.

Guarantees and contracts
  • The key, the reduced hash and the DRBG state (K, V) are secret; the state is wiped on destruction.
  • Constant time except for one rejection test per candidate (k = 0 or k >= q), whose outcome is public in effect: for secp256k1 it happens with probability below 2^-127.
  • constexpr, no allocation, noexcept.
Errors

None.

Examples
// RFC 6979 A.2.5: P-256's order, its test key, SHA-256("sample")
const auto order = hex<32>("ffffffff00000000ffffffffffffffffbce6faada7179e84f3b9cac2fc632551");
const auto key = hex<32>("c9afa9d845ba75166b5c215767b1d6934e50c3db36e89b127b8a622b120f6721");
const auto hash = snicholls::crypto::detail::sha256::hash(snicholls::crypto::test::bytes_of("sample"));
snicholls::crypto::secp256k1::rfc6979 nonces(key, hash, order);
const auto k = nonces.next(); // the first candidate in [1, q - 1]; next() again if r or s came out zero
Performance

Two HMACs per candidate after six for the set-up; included in the signing benchmark.

Tests and demos

tests/secp256k1/rfc6979_test.cpp: RFC 6979 A.2.5 ("sample" and "test", P-256, SHA-256) and the secp256k1 nonces widely published with libraries' test suites; demos/secp256k1/rfc6979_demo.cpp.

Dependencies

<array>, <cstdint>, <span>; the library's HMAC-SHA256.

Known issues and gotchas

The hash is reduced modulo q before use (bits2octets), as the RFC requires; passing an unreduced hash to a different implementation gives a different nonce for hashes at or above q.

Status

Experimental (0.1).

 The ECDH shared secret with a peer: the 48-byte big-endian x-coordinate of d Q.

Detailed Description

ECDH on P-384 (SEC 1 3.3.1, NIST SP 800-56A's primitive): the shared secret, the x-coordinate of d Q.

Overview

shared_secret(own private key, peer's public key) returns the 48 bytes both sides compute: the big-endian x-coordinate of d Q. It is TLS 1.3's secp384r1 key exchange (RFC 8446 7.4.2) and JOSE's ECDH-ES Z on P-384, and like every ECDH output it is input to a KDF, never a key itself.

Relationships

  • p256/ecdh.hpp: the same agreement on P-256; curve25519/x25519.hpp on Curve25519.
  • Group: P-384.
Implementations and variants

One: point::mul (a 4-bit fixed window over complete addition) and the constant-time conversion to affine.

Guarantees and contracts
  • Constant time in the private key; the peer's key is public. Revealed on purpose (ct::declassify): whether d Q is the identity, which cannot happen for a key that public_key::parse accepted (P-384 has prime order).
  • The peer's point is checked to be on the curve again before it is multiplied (an invalid-curve attack would otherwise learn d modulo the small factors of another curve's order: the complete formulas compute on any curve with a = -3), so a public_key built from an unchecked affine_point is refused, not used.
  • The result is in secret_bytes<48>; intermediates are wiped. constexpr, noexcept, no allocation.
Errors

errc::invalid_public_key when the peer's point is not on the curve, or d Q is the identity.

Examples
namespace p384 = snicholls::crypto::p384;
// RFC 6979 A.2.6's published test key and a fixed pattern; a real key comes from a CSPRNG
const auto alice = p384::private_key::from_bytes(
hex<48>("6b9d3dad2e1b8c1c05b19875b6659f4de23c3b667bf297ba9aa47740787137d896d5724e4c70a825f872c9ea60d2edf5")).unwrap();
const auto bob = p384::private_key::from_bytes(
hex<48>("0123456789abcdeffedcba98765432100123456789abcdeffedcba98765432100123456789abcdeffedcba9876543210")).unwrap();
auto z_alice = p384::shared_secret(alice, bob.public_key()); // result<secret_bytes<48>, errc>
auto z_bob = p384::shared_secret(bob, alice.public_key());
// A key built from a point that is not on the curve is refused, not multiplied
auto off = bob.public_key().point();
off.y = off.y + p384::field_element::from_u64(1);
const auto refused = p384::shared_secret(alice, p384::public_key(off)); // errc::invalid_public_key

Known issues and gotchas

The shared secret is not uniformly random: put it through a KDF (TLS's HKDF, JOSE's Concat KDF). An ephemeral key must be fresh for every exchange: the caller makes it from a system random source.

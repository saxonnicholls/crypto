Detailed Description

RSA signing (RFC 8017): RSASSA-PKCS1-v1_5 with SHA-256, SHA-384 and SHA-512 (RS256, RS384, RS512), with a private key held in constant time.

Overview

rsa::private_key holds the two primes and the CRT exponents (p, q, dP, dQ, qInv) and its public key; sign_pkcs1v15_sha256 (and _sha384, _sha512, each with a prehashed form) writes the signature, as long as the modulus. PKCS#1 v1.5 signing is deterministic: the same key and message always give the same bytes, the bytes every other implementation gives.

  • Keys: private_key::from_components (a JWK's n, e, p, q, dp, dq, qi, base64url-decoded), from_pkcs1_der (an RSAPrivateKey, PEM's "RSA PRIVATE KEY") and from_pkcs8_der (an unencrypted PrivateKeyInfo with rsaEncryption, PEM's "PRIVATE KEY"). Moduli of 2048 to 4096 bits, two primes, each of at most 2048 bits. An encrypted key (EncryptedPrivateKeyInfo) is another structure and is refused as malformed.
  • Every key is checked when it is made: p and q odd and different, p q = n, dP < p, dQ < q, qInv q = 1 mod p, and then a whole signature is made and verified with the public key (a pairwise consistency test), which is what proves dP and dQ belong to e. A key that fails any of it is errc::invalid_private_key, never a key that signs wrongly later.
  • Every signature is verified with the public key before it is released (errc::signing_fault, the output zeroed, when it does not verify): a miscomputed CRT half, from a hardware fault or a damaged key, would otherwise reveal a prime to anyone holding the bad signature and the message (the Bellcore attack).

Strict input (CLAUDE.md rule 8): components have no leading zero byte; DER is DER (minimal lengths and integers, version 0, nothing trailing, no attributes or other primes).

Relationships
  • rsa/rsa.hpp: public_key and verification, the other half; detail/mont.hpp: the constant-time Montgomery arithmetic (shared with P-256 and P-384), make_mont_ct and mont_pow_ct.
  • Above this library: holding keys by id, rotation and a KMS are a signer's (core's signer contract), which calls these functions. The family's production RSA signer is the OpenSSL one above this library; this is the family's own implementation of the same operation.
  • Group: RSA.
Implementations and variants

One: m^d mod n by the Chinese remainder theorem (RFC 8017 5.1.2, the second form). m is reduced modulo each prime through Montgomery multiplication, each half is a fixed 4-bit-window exponentiation of exactly as many steps as the prime's limb count gives, Garner's recombination is one more Montgomery multiplication, and s = m2 + q h is a plain multiplication. The limb count N is 16, 24 or 32 (primes up to 1024, 1536, 2048 bits), chosen from the lengths of p and q.

Guarantees and contracts
  • Constant time in p, q, dP, dQ, qInv and every value derived from them: no branch, loop bound or memory index depends on them (Montgomery multiplication with a masked final subtraction, a table scanned whole, a fixed number of squarings and multiplications). Public: n, e, the message, and the byte lengths of p and q (they choose N; in DER they are in the clear).
  • Revealed on purpose (ct::declassify): whether a key passed its checks; a component's leading-zero and sign tests when it is read (they decide its length, not its value); the finished signature, to verify it (a signature is public; one that then fails to verify is zeroed and never returned).
  • No blinding: the arithmetic does not need it for timing. It would add protection against power and electromagnetic analysis, which this library does not claim anywhere (README, "Constant time").
  • The key wipes itself; every intermediate (residues, the window table, the CRT halves) is wiped.
  • constexpr, noexcept, no allocation. A key is about 2.6 KB.
Errors

errc::invalid_private_key for a key that is malformed, outside the limits, inconsistent, or that fails its consistency test (errc::non_canonical for a component with a leading zero byte); errc::invalid_length for an output that is not exactly modulus_bytes(); errc::signing_fault for a signature that did not verify after it was made. No error carries key material.

Examples
namespace rsa = snicholls::crypto::rsa;
// The DER of an unencrypted "PRIVATE KEY" (PEM's base64 decoded by the caller, into memory the caller wipes)
auto key = rsa::private_key::from_pkcs8_der(pkcs8); // checked, and proved by a signature, before it is a key
std::vector<std::uint8_t> signature(key ? key->modulus_bytes() : 0);
const bool signed_ok = key && rsa::sign_pkcs1v15_sha256(*key, message, signature).is_ok(); // RS256
const bool verifies = signed_ok && rsa::verify_pkcs1v15_sha256(key->public_key(), message, signature).is_ok();
// One bit of the key changed: refused when it is read, never a key that signs wrongly
auto damaged = pkcs8;
damaged[damaged.size() - 5] ^= 1;
const auto refused = rsa::private_key::from_pkcs8_der(damaged); // errc::invalid_private_key
Performance

Two exponentiations of half the modulus's length: about 2.5 N 64 N Montgomery multiplications of N limbs each. See BENCHMARKS.md, benchmarks/rsa/sign_benchmark.cpp. Several times slower than OpenSSL (no assembly, no dedicated squaring).

Tests and demos

tests/rsa/sign_test.cpp: every Wycheproof rsa_pkcs1_{2048,3072,4096}_sig_gen case byte for byte, each key read from PKCS#8 and from its components; keys that must be refused (inconsistent, out of range, malformed DER, an encrypted key); the fault check, by signing with a damaged CRT half. The secret paths are in the Valgrind check (tests/ct/secret_marking.cpp). demos/rsa/sign_demo.cpp.

Dependencies

<array>, <cstdint>, <span>; core's result.hpp, wide_mul.hpp and SHA-2.

Known issues and gotchas
  • Primality of p and q is not tested: a key made by a trustworthy generator is assumed. The checks catch damage and inconsistency, not a key built to be weak.
  • PEM is base64 text around DER: strip the armour and decode it first, into memory you wipe.
  • RSASSA-PSS signing is not here yet (it needs a random salt, so a random source).
Status

Experimental (0.5). Not the family's production signer.

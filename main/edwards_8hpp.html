Detailed Description

curve25519::point: edwards25519, -x^2 + y^2 = 1 + d x^2 y^2, with complete addition, constant-time scalar multiplication, and RFC 8032 point encoding.

Overview

The group Ed25519 signs in. Points in extended coordinates (X : Y : Z : T), x = X/Z, y = Y/Z, xy = T/Z, with the addition and doubling formulas of Hisil, Wong, Carter and Dawson (2008) for a = -1, which are complete on this curve (d is not a square): one formula for every pair of points, the identity included. On top of it:

  • mul(k, p) and mul_base(k): k p in constant time, a 4-bit fixed window whose table entry is read by scanning all sixteen entries with masks. The sixteen multiples of B are built by the compiler.
  • mul_add_public(a, b, q): a B + b q for verification, variable time (public data only).
  • encode / decode: RFC 8032's 32-byte form, y with the sign of x in bit 255.
  • is_small_order, mul_by_cofactor, is_torsion_free: the cofactor-8 helpers.
Relationships
  • curve25519/field.hpp, curve25519/scalar.hpp: the arithmetic underneath.
  • curve25519/ed25519.hpp: the signature scheme.

Implementations and variants

One. Faster libraries use precomputed tables for B in Niels form and signed windows; this is the short form whose secret paths are one instruction sequence for every scalar.

Guarantees and contracts
  • Value type, trivially copyable, no allocation; every member constexpr and noexcept.
  • operator+, dbl, mul, mul_base, encode, select: constant time in every argument.
  • decode, mul_add_public, mul_public, is_small_order, is_torsion_free, is_identity, operator==: variable time; public data only.
  • Decoding is strict (RFC 8032, section 5.1.3): y must be below p (a non-canonical y is rejected), x must exist, and x = 0 with the sign bit set is rejected. Small-order and mixed-order points decode (the caller decides).
Errors

None: an invalid encoding is std::nullopt.

Examples
using snicholls::crypto::curve25519::point;
using snicholls::crypto::curve25519::scalar;
const point a = point::mul_base(scalar::from_u64(3)); // constant time in the scalar
const point b = point::mul(scalar::from_u64(3), point::base()); // the same, for any point
const point c = point::mul_add_public(scalar::from_u64(1), scalar::from_u64(2), point::base()); // public: B + 2B
const auto encoded = a.encode(); // 32 bytes, RFC 8032
const auto decoded = point::decode(encoded); // strict: std::nullopt if invalid
const auto two_torsion = point::decode(snicholls::crypto::test::hex<32>(
"ecffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff7f")); // (0, -1), order 2
const bool small = two_torsion && two_torsion->is_small_order();
const bool prime_order = point::base().is_torsion_free();

Known issues and gotchas

Equality is projective (cross products): the same point has many (X : Y : Z : T).

Detailed Description

curve25519::field_element: arithmetic modulo p = 2^255 - 19, constant-time and constexpr.

Overview

The coordinates of Curve25519 (X25519's Montgomery form) and edwards25519 (Ed25519's twisted Edwards form). Five limbs of 51 bits, kept weakly reduced (each limb a little above 2^51 at most) between operations and reduced to the canonical value only when encoded. Every operation is constexpr and runs in time independent of the value.

Use it through edwards.hpp, ed25519.hpp and x25519.hpp; it is public so that tests can pin identities and callers can check coordinates.

Implementations and variants

One: 5 x 51-bit limbs (the "donna 64" representation). Products are 128-bit, taken from core's snicholls::detail::umul128 (one instruction at run time on GCC and Clang, four 32-bit multiplies in a constant expression or on MSVC). The 4 x 64 limbs of detail/limbs.hpp were not reused: 2^255 - 19 leaves one spare bit, so 51-bit limbs absorb the carries of additions without a carry chain and the reduction by 19 is one multiplication, where the 4 x 64 form would need its full fold after every addition.

Guarantees and contracts
  • Value type, trivially copyable, no allocation; every member constexpr and noexcept.
  • Constant time in the value for every operation: no branch or index depends on a limb. invert and pow22523 are fixed addition chains; sqrt_ratio is a fixed exponentiation followed by masked selections.
  • from_bytes ignores bit 255 (the caller decides what it means: the sign of x for Ed25519, nothing for X25519) and accepts the non-canonical values p to 2^255 - 1, which then behave as their residues; is_canonical tells them apart.
Errors

None: a missing square root is a zero mask from sqrt_ratio.

Examples
using snicholls::crypto::curve25519::field_element;
constexpr auto i = field_element::sqrt_m1();
static_assert(i.square() == -field_element::from_u64(1)); // sqrt(-1), checked by the compiler
const auto inv = field_element::from_u64(5).invert(); // 1/5, a fixed addition chain
std::uint64_t is_square = 0;
const auto root = field_element::sqrt_ratio(field_element::from_u64(9), field_element::from_u64(1), is_square);
const auto p_bytes = snicholls::crypto::test::hex<32>("edffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff7f");
const bool p_is_canonical = field_element::is_canonical(p_bytes); // p itself is not a canonical encoding

Measured inside the Ed25519 and X25519 benchmarks, not on its own.

Dependencies

<array>, <cstdint>, <span>; core's detail/wide_mul.hpp.

Known issues and gotchas

Two elements equal as residues can have different limbs; compare with ==, which compares canonical encodings.

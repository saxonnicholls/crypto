Detailed Description

AES-256-GCM (NIST SP 800-38D): authenticated encryption with associated data, 96-bit nonces.

Overview

The same shape as aead/chacha20_poly1305.hpp: aes256_gcm_seal writes the ciphertext and returns the 16-byte tag; aes256_gcm_open checks the tag in constant time and only then writes the plaintext. JOSE's A256GCM (JWE content encryption) and TLS's AES_256_GCM. The nonce is 96 bits, the length NIST recommends and JOSE uses; other lengths are not offered.

Relationships
  • detail/aes.hpp (AES-256 without tables, GHASH); aead/chacha20_poly1305.hpp (the same interface); aead/aes_key_wrap.hpp (A256KW).
  • Group: Authenticated encryption.
Implementations and variants

One: counter mode from J0 + 1 with J0 = nonce || 0^31 || 1, GHASH over the associated data and the ciphertext with their lengths, the tag E(K, J0) XOR GHASH. AES computes its S-box (no tables) and GHASH multiplies bit by bit with masks.

Guarantees and contracts
  • Constant time in the key, the plaintext and the tag: no memory index or branch depends on them; lengths and the nonce are public. Revealed on purpose: whether the tag matched.
  • open writes nothing it has not authenticated; on a mismatch the output is zeroed.
  • In place allowed. constexpr, noexcept, no allocation.
  • Slower than AES-NI or table implementations (each S-box value is computed): fine for cookies, tokens and JWE, not for bulk data; use ChaCha20-Poly1305 for that.
Errors

errc::invalid_length for an output of another length, or a message over 2^36 - 32 bytes; errc::authentication_failed from open.

Examples
namespace aead = snicholls::crypto::aead;
const auto key = hex<32>("feffe9928665731c6d6a8f9467308308feffe9928665731c6d6a8f9467308308"); // the specification's test key
const auto nonce = hex<12>("cafebabefacedbaddecaf888"); // never repeated under a key
const auto message = hex_bytes("d9313225f88406e5a55909c5aff5269a86a7a9531534f7da2e4c303d8a318a72");
std::vector<std::uint8_t> sealed(message.size()), opened(message.size());
const aead::tag tag = aead::aes256_gcm_seal(key, nonce, {}, message, sealed).unwrap();
const auto ok = aead::aes256_gcm_open(key, nonce, {}, sealed, tag, opened);
auto bad = tag;
bad[15] ^= 1;
const auto refused = aead::aes256_gcm_open(key, nonce, {}, sealed, bad, opened); // authentication_failed
Performance

About 100 us for 64 bytes and 1 MB/s for longer messages (Release, Xeon W-3245): roughly 200 times slower than ChaCha20-Poly1305 here, the price of computing AES's S-box without tables or AES-NI. Fine for JWE's keys and short payloads; use XChaCha20-Poly1305 for cookies and bulk data. See benchmarks/aead/aes256_gcm_benchmark.cpp.

Tests and demos

tests/aead/aes256_gcm_test.cpp: the GCM specification's test cases 13 to 16 (AES-256), every Wycheproof aes_gcm_test.json case with a 256-bit key, a 96-bit nonce and a 128-bit tag, in-place use; tests/aead/aes256_gcm_oracles_test.cpp: OpenSSL and Node's crypto. The secret paths are in the Valgrind check. demos/aead/aes256_gcm_demo.cpp.

Dependencies

<array>, <cstdint>, <span>; core's result.hpp.

Known issues and gotchas

A 96-bit nonce must never repeat under one key: a repeat reveals the authentication key. With random nonces keep to well under 2^32 messages per key, or use XChaCha20-Poly1305.

Status

Experimental (0.4).

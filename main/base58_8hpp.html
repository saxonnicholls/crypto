Detailed Description

Base58 with any 58-symbol alphabet (Bitcoin, XRPL, Flickr): strict, allocation-free, constexpr.

Overview

Base58 writes bytes as a big number in base 58, with each leading zero byte written as the alphabet's first symbol. It is the text of Bitcoin's legacy addresses and keys (through base58check.hpp), XRPL's addresses (the same scheme, another alphabet), Solana's public keys and IPFS's CIDv0 (raw, no checksum).

  • base58_encode<MaxBytes>(bytes, alphabet) and base58_decode<MaxBytes>(text, alphabet) return core's containers::inplace_vector; base58_encode_to / base58_decode_to write into a caller's span.
  • The alphabet is a value: bitcoin_base58, xrpl_base58, flickr_base58, or make_base58_alphabet(...).

Decoding is strict: any character outside the alphabet (whitespace, 0, O, I, l in Bitcoin's) is errc::invalid_character; nothing is trimmed or repaired. The empty text is the empty byte string (as in Bitcoin Core's vectors).

Use base58check (base58check.hpp) for anything a person types: raw base58 has no checksum.

Relationships

  • address/bech32.hpp: the other address text.
  • snicholls::containers::inplace_vector (core): the fixed-capacity results.
  • Group: Addresses.
Implementations and variants

One: the schoolbook conversion between base 256 and base 58, O(n^2) in the length, done in the output buffer.

Guarantees and contracts
  • Every function is constexpr and noexcept; nothing allocates; the alphabets are built by the compiler.
  • Not constant time: the work depends on the number of leading zeros and on each digit. Addresses and public keys are public data. See "Known issues" for text that carries a secret.
  • Inputs are capped at MaxBytes bytes (default base58_default_max_bytes, 128) or the matching text length (base58_encoded_capacity(MaxBytes)), because the cost grows with the square of the length: 128 bytes is ample for every address, key and extended key, and bounds a hostile input to microseconds.
Errors

errc::invalid_length (input over the cap, or output span too small), errc::invalid_character (decode only).

Examples
namespace address = snicholls::crypto::address;
const std::array<std::uint8_t, 4> bytes{0x00, 0x00, 0x28, 0x7f};
const auto bitcoin = address::base58_encode(bytes); // "1145k": "11" for the two zero bytes
const auto xrpl = address::base58_encode(bytes, address::xrpl_base58); // "rrhnk": a zero byte is an "r" in XRPL's
const auto flickr = address::base58_encode(bytes, address::flickr_base58);
const auto back = address::base58_decode(std::string(bitcoin->data(), bitcoin->size()));
const auto refused = address::base58_decode("11O0"); // 'O' and '0' are not digits
std::array<char, 16> buffer{}; // or into a buffer of your own
const auto written = address::base58_encode_to(bytes, buffer);
Performance

benchmarks/address/base58_benchmark.cpp, macOS x86-64 (Xeon W-3245, 3.2 GHz), Apple Clang 17, Release, 2026-11-20: a 25-byte address encodes in 0.54 us and decodes in 0.29 us. The cost is quadratic in the length.

tests/address/base58_test.cpp (Bitcoin Core's base58_encode_decode.json, XRPL's special addresses, every boundary of the caps, every rejected character), demos/address/base58_demo.cpp.

Dependencies

<array>, <cstddef>, <cstdint>, <span>, <string_view>; core's result.hpp and containers/inplace_vector.hpp.

Known issues and gotchas

Wallet Import Format keys and xprv text are base58 of a secret. This codec is not constant time, so the time to encode or decode them depends on their digits. That is the accepted practice (every wallet does the same) because the text exists only to be shown to, or typed by, a person: an attacker who can time it closely can usually read the screen. Keep secrets in binary form (secret_bytes) and convert to text only at that boundary.

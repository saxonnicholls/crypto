Detailed Description

Ed25519 (RFC 8032): key pairs from a 32-byte seed, deterministic signatures, and verification.

Overview

Pure Ed25519 as RFC 8032 defines it (not Ed25519ph or Ed25519ctx). A key_pair is made from a 32-byte seed (the RFC's private key): SHA-512 of the seed gives the clamped secret scalar and the nonce prefix. sign is deterministic (no randomness, so no nonce reuse); verify checks a signature against a public key.

Verification rule, stated exactly (the "cofactorless" equation, as Go's crypto/ed25519 and libsodium's default verifier use):

  1. The public key A must decode strictly (curve25519::point::decode): y below p, x defined, no "negative zero". Otherwise errc::invalid_public_key.
  2. S must be canonical, S < L. Otherwise errc::invalid_signature (this is what stops S + L malleability).
  3. k = SHA-512(R || A || M) mod L, and the signature is valid exactly when the encoding of [S]B - [k]A equals the 32 bytes R, byte for byte. R is not decoded on its own, so a non-canonical R can never match.

Accepted: small-order and mixed-order public keys and R values whenever the equation holds (Wycheproof marks these "acceptable"; libsodium's strict mode rejects small-order A and R, which a caller can add with point::is_small_order). Rejected: S >= L, a public key that does not decode, every non-canonical R, and the signatures that only a cofactored equation ([8][S]B = [8]R + [8][k]A) would accept. Different verifiers disagree on those edge cases (see "Taming the many EdDSAs", Chalkias, Garillot and Nikolaenko, 2020); this one matches Go.

Implementations and variants

One.

Guarantees and contracts
  • key_pair::from_seed, key_pair::sign, public_key_from_seed: constant time in the seed and the secret scalar; the message's length and content are public. The seed, the secret scalar and the prefix live in secret_bytes and are wiped with the key pair; the nonce, the expanded hash and other intermediates are wiped before returning.
  • verify: variable time; its inputs are public.
  • Everything is constexpr and noexcept; no allocation (the message is hashed as a stream, twice when signing).
Errors

verify returns errc::invalid_public_key when A does not decode and errc::invalid_signature for every other failure, without saying which check failed.

Examples
namespace ed25519 = snicholls::crypto::ed25519;
// The seed is the private key: from a CSPRNG, or SLIP-10. This is RFC 8032's published TEST 2 seed.
const auto kp = ed25519::key_pair::from_seed(hex<32>("4ccd089b28ff96da9db6c346ec114e0f5b8a319f35aba624da8cf6ed4fb8a6fb"));
const std::uint8_t message[] = {0x72};
const ed25519::signature sig = kp.sign(message); // deterministic: no randomness
const auto ok = ed25519::verify(kp.public_key(), message, sig); // result<void, errc>
const std::uint8_t other[] = {0x73};
const auto bad = ed25519::verify(kp.public_key(), other, sig); // errc::invalid_signature

Known issues and gotchas

A seed is not a scalar: never pass SHA-512 output or a clamped scalar as a seed. Ed25519ph and Ed25519ctx are not implemented.

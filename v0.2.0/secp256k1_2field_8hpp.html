Detailed Description

secp256k1::field_element: arithmetic modulo p = 2^256 - 2^32 - 977, constant-time and constexpr.

Overview

The coordinates of secp256k1 points. Four 64-bit limbs, always fully reduced; addition, subtraction, multiplication, inversion and square roots with no branch or memory index that depends on the value. Every operation is constexpr, so tables of points (the multiples of G) are built by the compiler.

Use it through point.hpp; it is public so that callers can check coordinates and tests can pin identities.

Relationships
  • secp256k1/scalar.hpp: the same arithmetic modulo the group order n.
  • secp256k1/point.hpp: the curve y^2 = x^3 + 7 over this field.
  • Group: secp256k1.
Implementations and variants

One: 4 x 64-bit limbs with the 2^256 = c (mod p) fold, c = 2^32 + 977. libsecp256k1 uses 5 x 52 with lazy reduction, which is faster; this is the shortest constant-time form, and fast enough for wallets and servers (see the benchmarks).

Guarantees and contracts
  • Value type, trivially copyable, no allocation; every member constexpr and noexcept.
  • Constant time in the value for every operation, including inverse (Fermat, a fixed public exponent) and sqrt (one fixed exponentiation, then a constant-time check).
  • from_bytes rejects (returns std::nullopt) a value at or above p; that branch is on the validity of an encoding, which is public in every use here.
Errors

None: an invalid encoding is std::nullopt, a missing square root is std::nullopt.

Examples
using snicholls::crypto::secp256k1::field_element;
constexpr auto seven = field_element::from_u64(7);
constexpr auto inv = seven.inverse(); // computed at compile time
static_assert(inv * seven == field_element::from_u64(1));
const auto root = (seven * seven).sqrt(); // a square root, for public data
const bool root_ok = root && (*root == seven || *root == -seven);
const auto too_big = field_element::from_bytes(snicholls::crypto::test::hex<32>(
"fffffffffffffffffffffffffffffffffffffffffffffffffffffffefffffc2f")); // p itself: rejected

Known issues and gotchas

Evaluated in a constant expression (a constexpr variable, a static_assert), an inversion, a square root or anything longer costs more evaluation steps than the compilers allow by default; how many depends on the compiler and its standard library (Clang 21 with libstdc++ 15 exceeds Clang's default on one inversion). Raise the limit for such a translation unit: -fconstexpr-steps=100000000 (Clang), -fconstexpr-ops-limit=4294967296 -fconstexpr-loop-limit=100000000 (GCC), /constexpr:steps100000000 (MSVC), as this library's tests and demos do (snicholls_crypto_constexpr_limits in CMakeLists.txt). Evaluation at run time is unaffected.
